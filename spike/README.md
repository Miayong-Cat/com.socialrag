# 0단계 스파이크 — 기준표를 PDF에서 뽑을 수 있는가?

## 결론

**뽑을 수 있다. 단, 표 추출이 아니라 "텍스트 + 정규식"으로.**

| 방법 | 결과 |
|---|---|
| 선 기반 표 추출 (pdfplumber, PyMuPDF) | ❌ 페이지 테두리를 큰 표 하나로 인식 → 셀 어긋남, 7인가구 열 누락 |
| 페이지 텍스트 추출 + 정규식 | ✅ 행 단위로 깨끗, 숫자 손실 없음, 자체 검증 통과 |

→ 앞으로 **숫자 기준표**는 텍스트+정규식으로 JSON에 고정(판정 엔진용),
**서술형 본문**은 텍스트 청킹(RAG용)으로 처리한다.

## 파일

| 파일 | 하는 일 | 실행 |
|---|---|---|
| `table_scout.py` | 키워드가 나오는 페이지 찾기 / 페이지 표 덤프 | `python spike/table_scout.py [쪽번호...]` |
| `parse_criteria.py` | 기준 중위소득·급여별 선정기준 → JSON | `python spike/parse_criteria.py` |

- 입력: `data/raw/2026_국민기초생활보장_사업안내.pdf` (p.14, 인쇄 xii쪽)
- 출력: `data/processed/criteria_2026.json`

## 검증 방법

`parse_criteria.py`는 저장 전에 원문 숫자끼리 맞는지 확인한다.

- 급여별 선정기준 = 기준 중위소득 × 비율(32·40·48·50%) — **원 단위 반올림** (버림 아님)
- 생계급여 8인 이상 증가액 = 기준 중위소득 증가액 × 32%

하나라도 다르면 에러로 멈춘다 → PDF 형식이 바뀌어도 잘못된 숫자가 조용히 저장되지 않는다.

## 주의

- 원본 PDF는 공공누리 4유형(변경·상업적 이용 금지) → `data/`는 커밋하지 않는다.
- 8인 이상 증가액은 원문에 **기준 중위소득과 생계급여만** 나온다. 다른 급여는 판정 엔진(3단계)에서 계산 규칙을 정한다.
